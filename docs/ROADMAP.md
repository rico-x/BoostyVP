# BoostyVP: план развития

Цель — привычный по SmartTube интерфейс и управление, но для подписок Boosty.
Русский язык, тёмный спокойный интерфейс, отсутствие рекламных блоков и
необязательной аналитики. Не менять изображение и не добавлять программные
«улучшайзеры»: цвет, HDR и обработка остаются задачей источника/телевизора.

Ориентир: [официальный проект SmartTube](https://github.com/yuliskov/SmartTube),
в частности его настраиваемое управление, скорость просмотра и обновления.
Это план самостоятельной реализации; копирование чужого кода/графики не требуется.
Будущие пункты ниже не заявляются как уже работающие функции.

## Текущая база — 0.2.1

Уже есть подписки, авторы, видео, нативный плеер, качество/скорость,
локальная позиция просмотра, QR/телефонный вход. Исправлено получение фокуса
плеером после загрузки и возврат к предыдущей карточке. Полное переименование
включает новый applicationId, namespace, классы, тему, ресурсы, браузерное
подключение, сборочные файлы и документацию. Старые авторские сведения
сохраняются отдельно в NOTICE и истории Git.

Первая согласованная итерация: графитовый фон, красные акценты, компактные
карточки и постоянное левое меню с реальными действиями «Подписки», «Обновить»,
«Плеер», «Выйти». Добавлены сохраняемые шаги перемотки и таймер панели,
запоминание скорости, вызов панели кнопкой Menu. Рабочая основа Media3 и
данные входа сохранены. История, избранное и поиск пока не добавлены.

Следующее исправление добавляет чтение публикаций без видео и их отображение
в общей ленте/странице автора. Комментарии и ответы свёрнуты, загружаются по
запросу с постраничной навигацией; никаких отправок или реакций от пользователя.

Первый новый раздел каркаса — «Новое»: собственная лента Boosty
(`v1/feed/post/`) по всем подпискам одной сеткой по дате, с подгрузкой страниц.
Раздел выбирается в левом меню, «Назад» возвращает к подпискам, возврат из
плеера сохраняет прокрутку и карточку; маршрут фокуса покрыт `NewFeedFocusTest`.

## Очерёдность

| Этап | Что делаем | Проверяемый результат |
|---|---|---|
| 1. Каркас как у SmartTube | Левое меню: Главная, Подписки, Новое, Продолжить, История, Избранное, Поиск, Настройки. Единые карточки, горизонтальные ряды, крупный фокус, последовательные переходы пультом. | Все разделы доступны без мыши; Home/Back не теряют выбранную карточку и прокрутку; нет пустых разделов-заглушек, выдаваемых за готовые. |
| 2. Личная библиотека | Полная локальная история, «Смотреть позже», избранные авторы/видео, отметка просмотренного, продолжение с позиции, фильтр нового. | Состояние сохраняется после перезапуска, ведётся отдельно для аккаунтов; доступны удаление истории и явное управление приватностью. |
| 3. Плеер уровня SmartTube | Настраиваемые кнопки и шаг перемотки, последовательное быстрое/долгое нажатие, понятный seek-индикатор, субтитры/аудиодорожки при наличии, запоминание скорости и качества, очередь и отключаемый автопереход. | Пауза, повторный вызов панели, Back, качество, конец видео и возврат из системных окон не теряют фокус; ручной выбор качества не сбрасывается незаметно. |
| 4. Поиск и каталог | Поиск по автору/подпискам, сортировка по дате/длительности/просмотренности, фильтры, подробная карточка видео, контекстное меню долгим OK. | Честно указан охват поиска. Пока нет подтверждённого серверного поиска Boosty, локальные результаты не называются поиском по всему сервису. |
| 5. Кастомизация | Настройка порядка и видимости разделов/рядов, размера карточек и текста, плотности сетки, акцентного цвета, анимаций и кнопок плеера. | Настройки сохраняются, имеют безопасные значения по умолчанию и сброс; при любой конфигурации можно добраться до настроек пультом. |
| 6. Выпуски и интеграции | Подписанные обновления с журналом изменений и проверкой подписи, экспорт несекретных настроек, MediaSession, каналы Google TV/Projectivy после проверки совместимости. | Обновление сохраняет вход и историю, не заменяет приложение с чужой подписью; рекомендации включаются пользователем и не возвращают рекламную ленту. |

По уточнённому приоритету пользователя сначала выполнена ограниченная часть
**этапов 1 и 3** — визуальный стиль и базовые настройки плеера. Полное меню
из таблицы не создаётся заранее: новые разделы появляются вместе с работающим
содержимым. Следующая отдельная итерация — личная библиотека и продолжение
просмотра; объём определяется после проверки текущего интерфейса на ТВ.

## Следующая итерация: библиотека и навигация

1. Развивать существующий каркас «левое меню + область контента», сохраняя
   проверенную навигацию пультом; сворачивание меню добавлять отдельно.
2. Расширить карту фокуса для новых разделов: меню → ряд → карточка → плеер
   → исходная карточка. Текущий маршрут покрыт инструментальными тестами.
3. Разделить загрузку подписок, авторов и новых публикаций; кешировать данные
   и изображения, отменять лишние запросы при уходе с экрана.
4. Для истории/избранного использовать версионируемую локальную БД с ключом
   аккаунта. Текущие позиции из SharedPreferences переносить отдельной миграцией,
   а не терять при первой установке новой схемы.
5. Настройки интерфейса хранить отдельно от данных библиотеки и секретов.
6. Сначала согласовать читаемость с 2,1 м и на 75-дюймовом экране, затем переносить
   тот же сценарий в остальные разделы.

## Ограничения и зависимости

- Глобальный поиск, облачная синхронизация истории, комментарии, live и
  таймлайн-превью зависят от подтверждённых возможностей Boosty. Перед обещанием
  функции — read-only исследование протокола и тестовые ответы; доступ к закрытым
  публикациям не обходится.
- SponsorBlock и YouTube-специфичные рекомендации пропускаются: для Boosty
  нет подтверждённой совместимой базы. Они не блокируют основные доработки.
- Не переписывать рабочий Media3-плеер и сетевой слой ради внешнего сходства.
  Редизайн проводится поверх проверенной основы, по одному сценарию за итерацию.
- Android TV 32-bit, ARMv7 и пульт TCL остаются обязательной тестовой целью.
- Учесть standby/перезапуск, потерю сети и повторное открытие окна входа.
  Первый локальный прогон показал нестабильность теста перезапуска pairing-сервера:
  исследовать отдельно, не маскировать отключением проверок.

## Качество и безопасность каждого выпуска

- Локальная сборка → модульные тесты → инструментальные тесты на ТВ → ручная
  проверка публикации/видео → локальный коммит. Публикация в GitHub — только
  по отдельному явному запросу, не автоматически после проверки.
- Обязательные регрессии: D-pad, pause/play/seek, Back, таймер панели,
  вторичное окно, возврат в ленту, вход/обновление сессии и сохранение данных.
- Не логировать пароль, токены, содержимое сессии и приватные адреса видео.
  Не включать их в резервные копии, скриншоты CI или GitHub.
- Отдельной задачей убрать небезопасный silent fallback хранения токенов в
  обычных preferences: проблемы Android Keystore должны явно сообщаться,
  а не незаметно понижать защиту.
- Ключ подписи — локально вне репозитория. Выпуски имеют отдельные заметки и
  безопасный откат совместимым исправительным выпуском с новым versionCode,
  а не требованием удалить приложение ради установки старого APK.
