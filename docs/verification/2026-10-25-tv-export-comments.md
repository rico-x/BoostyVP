## B5: экспорт настроек

Причина исходной ошибки подтверждена: CREATE_DOCUMENT для JSON обрабатывает
только `com.android.tv.frameworkpackagestubs/.Stubs$DocumentsStub` с системным
уведомлением об отсутствии приложения. Настоящего DocumentsUI на этом ТВ нет.
Установленный Cx умеет GET_CONTENT/OPEN_DOCUMENT и ACTION_SEND через
`com.alphainventor.filemanager.activity.SaveToActivity`, но не CREATE_DOCUMENT.

Новая реализация предлагает выбор подходящего приложения: настоящий
CREATE_DOCUMENT предпочтителен; резервный путь — копия JSON через ACTION_SEND
в файловый менеджер, который также объявляет выбор документов. Плееры,
торрент-клиенты и системные заглушки отфильтрованы. Это проверка заявленных
возможностей, а не гарантия функции сохранения у любого стороннего приложения.

Копия находится в отдельном частном cache-подкаталоге с уникальным URI.
FileProvider открывает только эту область; получателю выдаётся временное чтение,
без прав записи и доступа ко всем файлам. Повторный экспорт не меняет уже
переданную копию. Снимок содержит только whitelist настроек BackupSchema.
Подпись после передачи честно предлагает выбрать папку и подтвердить запись
в выбранном приложении: ACTION_SEND не сообщает о фактическом сохранении.
При отсутствии обработчика доступна уже существующая передача через браузер/QR.

## B6: комментарии к видео

Общее меню долгого OK на видеокарточке использует отдельный маршрут комментариев
с blogUrl/postId. Свежая публикация загружается авторизованным BlogRepository;
плеер, медиасессия и запись истории для чтения не создаются.
Тот же PostReader отображает сразу раскрытые комментарии и прежние ответы,
пагинацию, повтор запроса и ограничения доступа. Тело/видео поста не запускаются.
Диалоговый маршрут сохраняет каталог под ним; Back возвращает выбранную карточку.
Все новые строки находятся в пакетах RU/EN.
