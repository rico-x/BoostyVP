# Безопасность

[English](SECURITY.en.md) · [Документация](docs/README.md)

Разработка ведётся в `main`; после публикации поддерживается последний выпуск.
Фиксированного SLA, независимого аудита и гарантии отсутствия уязвимостей нет.

## Сообщить об уязвимости

Используйте [приватную форму GitHub](https://github.com/rico-x/BoostyVP/security/advisories/new).
Если она недоступна, откройте issue только с просьбой о безопасном контакте,
**без** эксплуатационных подробностей и секретов. Обычные ошибки — в Issues.
Укажите версию, Android/ABI, минимальное воспроизведение и влияние. Удалите
из материалов токены, cookies, пароли, ключи, QR/адреса сопряжения,
платный контент и подписанные медиассылки.

## Известные ограничения

- Браузерный вход использует временный HTTP-сервер ТВ. Шифрование конверта
  не аутентифицирует HTTP-страницу: ключ доступен участникам LAN. Только доверенная
  сеть; порт не открывать наружу, адрес/QR не распространять.
- При сбое Keystore токены сохраняются в обычных приватных preferences,
  с записью ошибки в журнал, без отдельного UI-предупреждения. На root/скомпрометированной
  ОС защита ниже. Формат и этот fallback сохранены по решению владельца.
- Локальная библиотека/настройки не зашифрованы как отдельное хранилище.
  Подтверждаемая выборочная очистка уже есть; удаление записи истории не удаляет
  её позицию. Выход не является полной очисткой данных.
- Экспорт файловому менеджеру даёт временное чтение одной копии настроек,
  без токенов. LAN-перенос настроек использует HTTP, поэтому требует доверенной сети.
- API неофициальный. Boosty/CDN/ОС вне контроля проекта; совместимость может измениться.

Усиление LAN-сопряжения и изменение fallback Keystore исключены владельцем
из плана. Это зафиксированное решение, а не устранение соответствующих рисков.

## Защита выпуска

PR-проверки не получают ключ подписи. Подписание выполняет отдельная задача
из `main` после Verify, в окружении `release`. Временный ключ удаляется
до загрузки артефактов. Сертификат закреплён в `build-support/release-config.json`.
Опубликованные APK/теги не перезаписываются; Actions закреплены commit SHA.

К каждому выпуску приложен файл происхождения SLSA (`*.intoto.jsonl`). Разбор
сетевых ответов и входящих запросов сопряжения проверяется фаззингом Jazzer:
[разработка](docs/DEVELOPMENT.md#фаззинг).

ClamAV, VirusTotal, CodeQL, dependency review, Dependabot, фаззинг и rulesets дополняют
проверку, а не доказывают безопасность. Наличие YAML не означает выполненный
прогон или включённые version updates форка. Фактическое состояние — в
[готовности к выпуску](docs/RELEASE_READINESS.md), проверка скачанного APK —
в [инструкции](docs/RELEASING.md#проверка-apk).
